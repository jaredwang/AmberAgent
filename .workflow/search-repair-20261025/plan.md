## 完成标准

- 每项发现记录真问题、收窄或排除结论及理由。
- 已确认问题有定点行为验证，修复落在实际 owner。

- 搜索/设置定点 JVM、app 编译及可用环境下的搜索设置 UI 验证完成；明确报告未具备的真实供应商/物理设备验收。

## Phase 0：独立复核与范围锁定

复核 15 项发现和仓内设计契约；确认免费来源预算、MiniApp adapter、旧开关合并等边界。检查可用设备、构建和 UI 入口。

## Phase 1：设置与密钥日志

修复显式空 enabled IDs 被回填；补 Brave 认证头脱敏；检查设置供应商列表、编辑器和开关的交互与布局。定点设置/日志验证后独立审查。

## Phase 2：供应商协议与完整请求取消

修复 SearXNG 字段、新闻 topic、Tavily 时间参数、Firecrawl 新闻截断、日期映射、智谱生成查询约束；让 HTTP 取消覆盖正文读取，并接通 Exa/智谱。用原始响应和延迟 HTTP 验证。独立审查。

## Phase 3：聚合与消费者闭环

保留已有五来源/十调用优先级预算，修正工具描述；修正错误去重及答案丢失；让 DeepRead 尊重内置开关；接通子代理来源点击。保持 MiniApp 的明确 adapter 边界。定点聚合/消费者验证后独立审查。

## Phase 4：集成与 UI 验证、交付

完成 app 编译/构建和可用设备上的搜索设置、供应商编辑、搜索结果/引用 UI 检查；只修可观察的错位、对齐、间距、尺寸及交互问题。独立最终审查，一次有限维护性审查，复跑受影响检查，交付证据与真实验收边界。

## 验证与授权
