# Independent provider second verification

Read-only follow-up of audit-providers.md and audit-response-api.md. No production/test edits, Gradle, provider-key use or device requests. OpenAI Docs skill applied; current official documentation fetched before source verification. HTML reference pages exceeded fetch size, so their official Markdown URLs were retrieved read-only with urllib.

## Accepted, with narrowed claims

- **AI-1 / P1 accepted.** `common/http/Request.await` owns cancellation only until response headers resume the continuation. ClaudeProvider.complete 109-114, ChatCompletionsAPI.generateText 135-148, Google complete and image endpoints then synchronously consume bodies outside an active Call cancellation owner. Dispatchers.IO does not cancel these socket reads. The existing `withCancellableCall` helper is the appropriate existing owner. Limit changes to demonstrated production body reads and retain Grok's replacement-call ownership; streaming EventSource already cancels. Need actual-provider delayed-body RED, not just helper tests.
- **AI-2 / P1 accepted.** Both complete and SSE call ChatCompletionsAPI.parseMessage. It only decodes primitive visible content; array fallback reads the first nested thinking item, never visible text chunks. Current Mistral docs explicitly specify list-shaped complete responses and a streaming transition containing closing thinking plus first TextChunk. Completion can lose the entire answer; current streaming models can lose the transition answer prefix, rather than necessarily every streamed token. Supported endpoint already has explicit Mistral request handling.
- **AI-3 / P1 accepted for supported conversational image continuation; plain-text impact narrowed.** Adapter 166/341 loses ordinary Text thoughtSignature. Both accumulation paths additionally drop empty signed Text and merge signature boundaries. Current Generate Content docs explicitly allow empty-text signature stream parts and prohibit concatenating signed parts with either signed or unsigned neighbors. Image generation docs describe signed first non-thought Text plus signed image parts and warn missing circulated signatures can fail subsequent responses. Plain text omission is recommended-continuity degradation, not a universal HTTP 400. Function-call/image metadata already preserved, so do not rewrite them broadly.
- **AI-4 / P2 accepted only as app-private plaintext-at-rest duplication.** Production DI passes Context to Claude/Google/OpenAI providers; KeyRoulette.lru persists raw rehydrated keys, even with one key. This bypasses the existing Keystore-backed credential storage contract. Cache is outside current backup include domains; no external exposure, network leak or backup disclosure established. Persisting stable fingerprints and rewriting legacy cache suffices; no encryption framework or new permission warranted.
- **RESP-1 / P1 accepted, opt-in stream scope.** Real UI switch exists at ProviderConfigurationFields 126-133 and only displays on strict official API-key + Responses configuration; capability defaults true. Fresh durable runs build ResponsesResumeRequest in ChatRunHooksFactory 397-425. ResponseAPI rechecks endpoint/toggle; encoder sends store=true yet omits background. Existing Stop genuinely calls /cancel through stored gateway and turns failed cancel into WAITING_EXTERNAL. Official docs specify background+stream for reconnect and background-only cancel, so this is a broken already-implemented feature rather than unsolicited background preference. Set background only for gated resumable streaming. Nonstream generateText must remain synchronous or explicitly use the existing stream-to-final path, never parse an immediately queued background response as a completed answer.
- **RESP-2 / P1 accepted.** storedRequest sets SSE Accept but neither stream=true nor starting_after. Official retrieve schema defaults stream=false. Reconnect, explicit same-run replay and recovery all call this request. Full rebuild deliberately needs no cursor suffix; automatic reconnect should send starting_after and preserve the known response ID even when suffix omits response.created. fetchStatus remains ordinary JSON retrieval.
- **RESP-3 / P2 accepted.** response.created sets in-memory ID then continues; only decoded visible chunks enter persistDrain. Stop/recovery gateway exclusively loads ResponseResumeStore, so created-only disconnect/stop has no durable identity. Checkpoint created through the ordered existing drain without synthesizing UI content. This becomes more costly once background creation works, but missing ownership is already directly present.

## Confirmed exclusions / cautions

- No justification to expand tool-image contracts, generated-image final-only reconciliation or opaque final-only reasoning handling absent a valid production protocol fixture.
- fc_ / call_ identity claim remains rejected: complete request history reconstructs paired call/output local IDs; no proven rejected request.
- Antigravity concurrent onboarding overwrite remains unproven; no production change justified.
- Optional plain-text Gemini signature omission alone is not a guaranteed provider error; keep image continuation and signed metadata integrity as the concrete finding.
- Responses feature is off by default at provider setting level, but opt-in settings and production owner path exist. Severity is scoped to users enabling it, not all OpenAI requests.
